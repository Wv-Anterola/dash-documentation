## Integrated projects now update capabilities

`npm run coverage` fails if an integrated record becomes stranded in history.

## What integration looks like in the product

An integrated project should stop reading like a disconnected demo. Its
project record explains provenance; its feature guide explains the complete
workflow; its capability pages explain the older Dash concepts it extended;
and its architecture pages identify the implementation and persistence path.

The current Trip Planner preset is a visible example. The project-shaped
experience is helpful, but it is assembled from existing Dash capabilities:
dashboard creation, a freeform canvas, embedded documents, shared fields, a
Mapbox document, links, resources, and an AI-assisted tool.

![The New Dashboard dialog showing Trip Planner as an integrated preset rather than a separate application.](/assets/images/current/dash-trip-planner-preset.webp)

Its [operating guide](/guides/features/trip-planner/) documents the complete
workflow. The [workspace capability](/capabilities/platform/), [map
guide](/guides/documents/map/), [link model](/concepts/links/), and [AI
capability](/capabilities/ai-automation/) document the reusable parts behind
it. That is the expected documentation path for every integrated project.

## How to read the status column

A project counts as integrated only if its behavior is reachable in the current
application: a document type registered in `Documents.ts`, an entry in
`CollectionViewType`, a tool constructed in the agent registry, or code one of
those paths calls.

A merged branch does not qualify on its own, and neither does a demo recording,
a screenshot, or a finished report. Several projects below have all three and
are still not in the application. Each write-up records what was checked.

## Where the work went

Counted by system area, which is a rough map of what the group has spent seven
years on.

  </thead>
  <tbody>
    {areas().map((a) => {
      const inArea = projects.filter((p) => p.area === a);
      const integ = inArea.filter((p) => p.status === 'integrated').length;
      return (
        <tr>
          <th scope="row">{a}</th>
          <td>{inArea.length}</td>
          <td>{integ}</td>
        </tr>
      );
    })}

The document model and the agent system dominate, for different reasons.
Document types are the cheapest thing to add, so that is what a one-semester
project often becomes. The agent system is recent and concentrated: nearly all
of it arrived in 2025 and 2026, on top of the tool registry.
