Press <kbd>Ctrl/Cmd</kbd> + <kbd>F</kbd>. If exactly one selected document has
its own search implementation, Dash searches inside that document. Otherwise it
opens the global search panel.

## Global search

Global search walks the current workspace recursively, including documents
nested in collections, annotations, and collection sidebars. If documents are
selected when the search begins, those documents become the roots instead of
the entire docking view.

Results update 300 milliseconds after typing stops. Each result shows:

- its title;
- a short document or collection-view type;
- the field names that matched.

Click a result to select and reveal it. If its view supports in-document search,
Dash also passes the query into that view. <kbd>Shift</kbd>-click passes the
backward-search flag, which is useful for moving to a previous match in a PDF.

## What a query matches

By default, Dash converts searchable field values to text and performs a
case-insensitive substring match. Depending on the document, this can include:

- title, author, tags, and user-defined fields;
- rich-text content stored as a document field;
- captions, descriptions, transcripts, and other text-valued metadata;
- fields inherited through document prototypes.

The result's matched-field list is the best explanation of why it appeared.

Prefix the query with `=` for a case-insensitive exact field-value match:

```text
=reviewed
```

Choose **Keys** in the type selector to match field names rather than values.
This is useful when you remember that a corpus has a `reviewStatus` field but
not which documents carry it.

## Type filtering

The selector can show all results or restrict the visible list to:

- rich text;
- image;
- PDF;
- web;
- video;
- audio;
- collection;
- field-name matches.

Changing the type does not run the search again. It filters the result set
already in memory.

## Ranking

Matching documents are not sorted only by title or creation date. Dash builds a
graph over the result set from the links between those documents and runs a
small PageRank calculation—at most 25 iterations, with a damping factor of
0.9. Better-connected matching documents therefore tend to appear first.

This makes explicit links part of retrieval rather than decoration. It also
means two workspaces containing the same text can order their results
differently if their link structures differ.

## Boundaries

Global search is field-based. It can match rich text when that text is stored in
a searchable field, but it does not build a general full-text index over every
byte of every imported file.

In particular:

- a PDF can search its rendered text internally, but the global panel first
  needs a matching searchable field to return that PDF;
- a webpage's live DOM is not crawled as a general search corpus;
- binary image and video content is not searched visually;
- script, configuration, key-value, button, font-icon, and presentation-slide
  document types are deliberately excluded from global results;
- some internal layout fields are marked non-searchable and removed from the
  match list.

For questions over document contents, the chatbot's chunking and retrieval path
is a different system. See [AI and automation](/capabilities/ai-automation/).
Retrieval can find semantically relevant passages, but its output must be
checked against the cited source.

## Link-target search

The same search component appears while creating a link. In that mode:

- the type selector is hidden;
- selecting a result creates the link instead of navigating;
- destinations already linked from the source are styled differently;
- the active text or media selection can become the target anchor.

See [links and annotations](/capabilities/connections-and-trails/#links-and-annotations)
for the complete linking workflow.

## Search versus filters

Use search to locate a document or passage. Use
[filters](/guides/properties/filters/) to keep a collection view narrowed to a
repeatable subset.

| Need | Use |
| :--- | :--- |
| Find the one document whose title contains “budget” | Global search |
| Find the previous “budget” occurrence inside a PDF | PDF search |
| Show only documents where `status = reviewed` | Filter |
| Ask a question across source text and receive citations | Chatbot retrieval |
| Find candidates related in meaning but without shared terms | Not available in the shipped search; see the recommendation project below |

## Troubleshooting

| Symptom | Check |
| :--- | :--- |
| A known document does not appear | Clear the current selection so search scopes the full docking view; then search its title or a stored field. |
| Too many partial matches | Prefix the query with `=`. |
| You remember the field, not the value | Choose **Keys**. |
| Result appears but the passage is not highlighted | The document matched metadata but its view does not implement content search, or that text is not available to the view. |
| Results look unexpectedly ordered | Ranking uses links among the matching documents. |
