---
title: Filters
description: Narrow a collection recursively by text, field value, tag, link state, permissions, or numeric range without removing documents.
---

Filters change which documents a collection renders. They do not delete,
detach, or rewrite the documents, and clearing the filter restores the full
view.

Select the collection or dashboard, open the properties panel, and expand
**Filters**. The panel evaluates the collection's children, nested documents,
annotations, and sidebar documents.

## Add a filter

Choose a field from **add a filter**. The list includes document fields and
several useful derived choices:

- guest access;
- linked-to state;
- Star, Heart, Bolt, and Cloud markers;
- tags and user-defined metadata.

The control Dash renders depends on the values it finds.

| Field shape | Filter control |
| :--- | :--- |
| Text content | Text input |
| Mostly numeric values | Two-handle range slider |
| Tags | One membership toggle per tag |
| Other discrete values | Checkboxes |

### Text

Enter the text and press <kbd>Enter</kbd> or leave the input. An empty value
removes the text filter.

### Discrete values

Select one or more values. The panel also preserves special any/none values
when the underlying field supports them. Values are gathered recursively, so a
field used only inside a nested collection can still appear.

### Numeric range

Dash classifies a field as numeric when fewer than ten percent of its observed
non-empty values fail numeric conversion. The slider's initial domain extends
slightly beyond the minimum and maximum so boundary values remain selectable.

Mixed units such as `10 kg`, `12 kg`, and `unknown` will usually force the field
back to checkbox mode. Store the number and unit in separate fields if the
range matters.

### Tags

Tag filters check membership in the `tags` list. A document may satisfy several
tag filters at once.

## Combining filters

The document model supports `AND` and `OR` across different fields, with
`AND` as the default. The selector for changing that operator is commented out
in the current panel, so do not rely on the user interface to switch existing
collections between the two.

Within one discrete field, selected values are represented as filters on that
field. Test the combination against a small known set before using it as a
research inclusion rule.

## Collapse or remove

The square control beside a field collapses its inputs. Active values remain in
force and are summarized under the heading.

The circular remove control clears that field's active value and range filters,
then removes the heading from the panel.

## Filter hotkeys

The second field selector, **add a hotkey**, creates a reusable filter control.
Hotkeys are stored in the user's filter-hotkey collection and can be assigned a
custom icon. They are useful for states applied repeatedly across dashboards,
such as starred items or a review status.

Because hotkeys are user-level objects, a colleague may not have the same
control even when both people can see the filtered collection. Document the
underlying field and value in a shared workflow.

## Saved filter state

Filter expressions are stored on the collection document in child-filter
fields. The properties implementation can also exchange active filters with a
filter document through `currentFilter`, preserving ordinary and range filters
separately.

This is why filters survive view changes and reloads: they belong to the
collection, not to the temporary panel.

## Reproducible filtering

For a filter used in analysis or review:

1. Normalize the field names and value spellings.
2. Record whether missing values should count.
3. Keep units out of numeric fields.
4. Capture the field, operator, and selected values in a note.
5. Check the visible count against a hand-verified sample.
6. Remember that nested and sidebar documents are included.

The interface is designed for interactive narrowing, not as a formal query
language. If an inclusion rule determines a published result, export or script
the matching IDs so the exact set can be audited.
