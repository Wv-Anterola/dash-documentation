A data-visualisation document keeps a dataset and its presentation together.
The same CSV-backed records can be shown as a table, line chart, histogram,
pie chart, or scatter plot. Changing the view does not create a second
dataset.

This is one of the clearest examples of an integrated research feature in
Dash. The original 2022 document type, later chart filtering, and the current
generation pipeline all contribute to the interface described here.

## Create one

Use any of these routes:

1. Import or drag a CSV file onto a canvas.
2. Copy tabular data and use `Ctrl+P` / `Command+P` when that paste workflow is
   available in the current browser build.
3. Open a collection in **Schema** view and create a data visualisation from
   the schema toolbar.

Dash removes completely empty rows before rendering. If the CSV cannot be
loaded or parsed, the document reports **Data not found** rather than silently
showing an empty chart.

## Prepare the dataset

Good charts begin with predictable columns:

- Give every column a unique, meaningful heading.
- Keep one kind of value in each column.
- Prefer plain numbers for quantitative axes.
- Use consistent spelling and capitalization for categories.
- Remove totals and explanatory footer rows from the chart range.
- Keep a stable identifier or name column, even if it is not plotted.

The current chart code tolerates some formatted numeric strings by stripping
characters such as currency signs and percent marks. That is a convenience,
not a substitute for cleaning the data. Empty or non-numeric values can be
excluded from a histogram or line series, and ambiguous formatting may produce
an unexpected scale.

## Choose a view

| View | Best for | Selection behavior |
| --- | --- | --- |
| **Table** | Inspecting records, choosing exact rows, and applying value or range filters | Select individual rows; use the platform modifier key to extend a selection |
| **Line chart** | Comparing one or two numeric series over a shared x-axis | Select plotted points when chart filtering is enabled |
| **Histogram** | Inspecting the distribution of one quantitative field | Select one or more bins |
| **Pie chart** | Comparing a small number of categories or parts of a whole | Select one or more slices |
| **Scatter plot** | Comparing two quantitative fields or exploring a generated semantic map | Select points; a point with a valid source-document ID can open that document |

Click a column heading to choose the columns and available chart type. The
first selected axis is shown in green; the second is red. With three numeric
columns in a line chart, the first acts as the shared x-axis and the other two
become plotted series.

![Selecting two columns for a two-dimensional chart](/assets/gifs/dataViz/2D_graph.gif)

![Plotting two selected series against a shared x-axis](/assets/gifs/dataViz/3colLinechart.gif)

### Keep a title column

Use **Select title column**, or shift-select a heading, to designate the
record label. Dash keeps that column available when the plotted axes change,
which makes selections intelligible after the chart no longer displays every
field.

![Setting a stable title column](/assets/gifs/dataViz/titleCol.gif)

## Select and filter records

Selection is stored on the data-visualisation document, so it can be shared by
the table and chart views.

### Select in the table

Click a row to select it. Use `Ctrl` on Windows/Linux or `Command` on macOS to
extend the selection rather than replace it.

The table filter supports:

- **Value** — select rows whose chosen column exactly matches one value.
- **Range** — select rows whose value falls between a start and end value.

![Selecting records with a table value or range filter](/assets/gifs/dataViz/filteringB.gif)

### Select in a chart

Enable **Select data to filter**, then click points, bins, or slices. The
interactive-filtering work merged into Dash added multi-selection and made
chart selections survive a refresh.

![Selecting records directly in a rendered chart](/assets/gifs/dataViz/filteringC.gif)

### Create a filtered document

Drag a column or use the filtered-document action to create a derived
visualisation. The new document represents the selected rows while the source
document remains the complete dataset.

![Creating and populating a filtered data document](/assets/gifs/dataViz/filteringA.gif)

This distinction is useful in analysis: the source is the population; a
filtered document is a named subset that can be placed, linked, or annotated
elsewhere.

## Create a visualisation from Schema view

Schema view already presents a collection as rows and fields. Its **DataViz**
action serializes that table into a CSV-backed visualisation:

1. Open the collection in [Schema view](/guides/views/schema/).
2. Confirm that the columns you need are visible and consistently typed.
3. Choose **DataViz** in the schema toolbar.
4. Return to Freeform view and place the resulting document.
5. Turn on **Display live updates to canvas** if the chart should track
   additions and deletions in the source collection.

![Creating a data visualisation from a schema table](/assets/gifs/dataViz/fromSchema_dataViz.gif)

Leave live updates off when the visualisation is evidence for a report and
must stay stable. Turn them on for monitoring views where freshness matters
more than reproducibility.

## Make a semantic map of documents

**Visualize Unstructured Data** turns a mixed selection of documents into a
two-dimensional similarity map. It is not the same operation as importing a
CSV: Dash first derives a numeric representation of each usable document,
then creates the CSV and scatter plot for you.

1. On a freeform canvas, marquee-select at least two documents.
2. Open the marquee menu.
3. Choose **Visualize Unstructured Data** (the project-diagram icon).
4. Wait while the browser loads the embedding model and processes the
   selection.
5. Inspect the new **Semantic Map** data-visualisation document.
6. Hover a point to read its label. Click it to select it and, when the row
   retains a valid `docId`, open the source document in the right tab.

The merged implementation can extract:

- plain or rich text;
- text from PDF pages;
- readable text fetched from a webpage; and
- an original-resolution image when the uploaded asset is reachable.

Documents with no extractable content are omitted. Dash uses the
`Xenova/clip-vit-base-patch32` text and vision models from Transformers.js to
create 512-dimensional embeddings in the browser, then runs principal
component analysis (PCA) in a Pyodide worker to reduce them to the `pc1` and
`pc2` columns plotted on screen. Generated embeddings are cached on the
backing CSV document so the same map does not have to recompute every vector.

This is an exploratory view, not a classification or proof of similarity.
Distance is affected by the model, the text Dash can extract, PCA, and the
particular documents selected. Treat nearby points as a prompt to inspect the
sources, not as a conclusion.

### Runtime requirements and limits

- The model is downloaded on first use, so the first map may take materially
  longer than later ones.
- The current embedding configuration requests WebGPU. Browser and graphics
  support therefore matter even though the rest of Dash is running.
- Webpage extraction depends on the configured CORS proxy and the remote page
  remaining reachable.
- Scanned PDFs without a text layer do not become searchable text through this
  path.
- Image processing depends on the original uploaded asset being available.
- The scatter plot needs two numeric axes. For a generated semantic map these
  are selected automatically as `pc1` and `pc2`.
- The result is a two-dimensional projection. It necessarily discards
  information from the original embedding.

A separate research variant experiments with a learned projection head and
moving the original freeform documents into the projected layout. Those changes
are not part of the current product behavior.

## Ask Dash to analyse the data

The context menu can expose **Analyze with AI** when the model-backed data
workflow is configured. It can:

- draft a general textual analysis;
- transfer that analysis into a text annotation;
- propose a line chart for a detected relationship; and
- open a follow-up chat about the dataset.

![Saving a generated analysis as a text annotation](/assets/gifs/dataViz/aiText.gif)

![Generating a visualisation for a detected relationship](/assets/gifs/dataViz/aiVisualize.gif)

![Asking follow-up questions about a dataset](/assets/gifs/dataViz/aiChat.gif)

Generated analysis is not a statistical guarantee. Check the selected columns,
units, missing values, sample size, and chart against the source CSV. The
feature also requires the relevant server and model credentials; see
[configuration](/reference/configuration/).

## Annotation and provenance

A chart can be annotated like other media documents. Before sharing an
interpretation, record:

- the source and retrieval date;
- what one row represents;
- units and any transformations;
- filters or excluded values;
- whether the document is live or a snapshot; and
- which columns and chart type support the claim.

Link the note to the visualisation and keep the raw CSV nearby. That makes it
possible to inspect the claim without reverse-engineering a screenshot.

## Troubleshooting

**The document says “Data not found.”** Confirm the CSV field still points to a
reachable uploaded asset and re-import the file if necessary.

**A numeric chart is empty.** Inspect blank cells, mixed types, commas, currency
symbols, and footer rows. Start with a one-column histogram to isolate the
problem.

**The axes are wrong.** Clear the selection and choose columns again in the
intended order. The first chosen column is the x-axis.

**Selections appear to disappear.** Return to the table and inspect the
selected rows. A chart may not render a selected record when its plotted value
is empty or invalid.

**Visualize Unstructured Data does nothing.** Select at least two documents.
If the selection is valid, check the browser console for model-download,
WebGPU, CORS, PDF, or worker failures.

**A semantic-map source was omitted.** Dash could not derive supported text or
image input from that document. For a scanned PDF, add an OCR-derived text
note; for a webpage, confirm that the URL can be fetched through the proxy.

**A semantic-map point does not open its source.** Point navigation depends on
the generated row retaining a valid Dash document ID. The scatter plot itself
still works when that identity field is absent or malformed.

**The AI action is missing or fails.** Verify the application configuration
and server logs. The underlying table and chart workflows do not require the
AI service.

  renderer and semantic-map path: browser-side CLIP embeddings, PCA, a
  generated CSV, and point-to-document navigation. Two later projection-head
  experiments remain on their development branch.
</ProjectNote>

## For maintainers

The main implementation is under
`src/client/views/nodes/DataVizBox/`:

- `DataVizBox.tsx` owns the CSV records, current view, axes, title column,
  selected rows, annotations, live-schema toggle, and AI entry point.
- `components/TableBox.tsx` implements row selection plus value and range
  filters.
- `components/LineChart.tsx`, `Histogram.tsx`, `PieChart.tsx`, and
  `ScatterPlot.tsx` render chart views and translate chart selections back to
  record identifiers.
- `SchemaCSVPopUp.tsx` creates a visualisation from a schema table.
- `utils/SemanticMapManager.ts` extracts supported document content, maintains
  the embedding cache, builds the derived CSV, and selects the scatter-plot
  fields.
- `utils/EmbeddingService.ts` loads the CLIP text and vision models and creates
  normalized embeddings.
- `utils/PyodideWorker.ts` sends the PCA work to the shared Pyodide worker.

The persisted view values are `table`, `lineChart`, `histogram`, `pieChart`,
and `scatterPlot`. Axes and selection state live on the layout document,
while the CSV field remains on the data document. That separation lets
multiple layouts present the same underlying records differently.
