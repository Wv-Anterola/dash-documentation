Everything you handle in Dash is a document: a note, PDF, image, video,
collection, link, trail, agent message, or specialized research surface.
Document types choose a renderer and a set of defaults; they do not create
separate storage systems.

This guide covers operations shared across types. Use the other pages in this
section for controls specific to text, media, maps, data visualization, and
other renderers.

## Create or import a document

### Create from the canvas

With a freeform canvas active, type a colon to open the document menu and choose
a type. Dash creates a blank instance from that type's prototype.

![Screen recording: creating a node in Dash.](/assets/gifs/gettingstarted/createnode.gif)

Developer mode exposes additional factories, including Script and experimental
document surfaces. See [interface modes](/getting-started/modes/).

### Drop a file or URL

Drag a supported local file or browser item onto a Dash canvas. The import path
creates a Dash document and stores or references the source according to its
type. Common routes include PDF, image, audio, video, webpage, text, and CSV.

A remote URL is not the same as a captured file. Webpage availability,
authentication, and content can change after the Dash document is created.
For durable research material, keep a captured or exported source when policy
allows it.

### Use the Imports panel

Open **Imports**, select the import control, and choose one or more files.
Imported documents appear in the panel and can be dragged into a working
collection. The panel is an intake area, not a second copy of each item.

### Create inside a structured view

Schema, stacking, notetaking, and other collection views provide a **+ New**
route in the view itself. The new document joins the same underlying collection
and receives whatever grouping or template context that view supplies.

**Single selection.** Click the document decoration or selectable surface. Its
decoration and context toolbar become active. Click a blank canvas region to
return selection to the collection.

**Additive selection.** Hold Shift while selecting documents. Dash creates a
shared selection box so the set can be moved, resized, grouped, collected, or
removed together.

**Marquee selection.** Drag a marquee over a canvas region to select documents
spatially. The marquee menu supplies operations appropriate to the selection,
including collecting or grouping it. Canvas shortcuts are listed in the
[keyboard reference](/reference/keyboard-shortcuts/).

**Content selection.** A text range, PDF region, media interval, or ink region
can become an anchor. Content selection is different from selecting the whole
document: links and annotations created from it target the region.

## Read the document decoration

When a document is selected, its surrounding decoration supplies the common
operations. The exact buttons depend on document type, interface mode, access,
and available space.

Typical controls include:

- an editable title;
- drag and resize handles;
- remove from the current collection;
- open or focus in another tab or tile;
- create or follow a link;
- pin to a presentation trail;
- open the context menu;
- type-specific actions such as playback, annotation, or text formatting.

The properties panel is the more complete inspection surface. It exposes data
fields, options, links, other contexts, filters, and—in Developer mode—layout
and permission controls.

## Data, layout, and contexts

A visible document is usually a layout delegate pointing to shared data.
That separation explains behavior that otherwise looks inconsistent:

| Change | Usually affects |
| :--- | :--- |
| Edit note text, source metadata, or a tag | Every context of the shared data |
| Move or resize an appearance | That context |
| Change a collection perspective | That collection appearance |
| Edit a `$`-prefixed field | The data document |
| Edit an ordinary layout field | The selected delegate or appearance |

Use [Other Contexts](/guides/properties/othercontexts/) to see where the same
document appears. Use a **copy** when content must diverge, another **context**
when content must remain shared, and a **link** when two distinct documents
need an explicit relationship.

The older interface sometimes calls another context an “alias.” In current
technical documentation, **embedding**, **delegate**, and **context** are more
precise because the new appearance can carry its own layout fields.

## Edit and arrange

Move a document by dragging its decoration. Resize it from its handles.
Document content remains live while arranged on a freeform canvas; resizing an
image, PDF, video, or nested collection changes its presentation box rather
than rewriting its source.

For many documents:

1. select the set;
2. choose move, resize, alignment, grouping, or collection behavior from the
   shared controls;
3. check whether the operation changed layout only or created a new collection;
4. undo immediately if the result is broader than intended.

A collection created from the selection is a first-class document with its own
fields and view type. A visual group is lighter-weight and tied more closely to
the current canvas arrangement.

## Link or annotate

Link whole documents when the complete items are the endpoints. Select a text
range, PDF/image/web region, timestamp, or ink stroke first when the
relationship is more precise.

An annotation is also a document. It keeps an `annotationOn` relationship to
its source and can itself be titled, tagged, placed in collections, or linked.
See [Linking](/guides/features/linking/) and
[Annotation and markup](/guides/features/markup/) for the complete controls.

## Remove, close, or delete

These actions are not interchangeable:

- **Remove from a collection** removes the current embedding from that
  container.
- **Close a tab or tile** removes a workspace view, not its underlying
  document.
- **Delete a context** can leave other contexts of the data intact.
- **Delete the underlying document** is broader and can affect links,
  annotations, and every context.

Check **Other Contexts** and use undo before treating an absent appearance as
proof that the data is gone. Recently closed material may remain available
through the Files panel.

## Access and persistence

Visible controls do not override permissions. View access permits reading;
augment access can permit adding without granting full edits; edit access
permits ordinary changes; admin access controls sharing. Data and layout can
have different effective permissions, which is why a collaborator may read
content but be unable to move its appearance.

Most edits are sent through Dash's document server and grouped by the undo
manager. Wait for the server connection to recover before assuming a change has
persisted. A page refresh is not a substitute for checking save/reload behavior
on a new document type.

## Troubleshooting

| Symptom | Check |
| :--- | :--- |
| The creation menu lacks an advanced type | Switch to Developer mode and confirm the type has a current factory |
| A dropped file does nothing | Supported type, upload directory, server connection, file size, and browser console |
| Editing one appearance changes another | You created another context, not an independent copy |
| Moving one appearance changes shared content | Confirm which field or nested document the operation targeted |
| A collaborator can read but not resize | Layout permission may be lower than data permission |
| A document disappears after filtering | Clear collection filters before assuming it was removed |
| A removed document still appears elsewhere | It has another embedding; inspect Other Contexts |
| A document returns blank after reload | Its factory, renderer, field serialization, or external source is incomplete |

## Technical path

`DocumentTypes.ts` declares registered types, `Documents.ts` constructs their
prototypes and instances, `DocumentContentsView.Init` maps types to renderers,
and `Doc.ts` supplies fields, prototypes, permissions, serialization hooks, and
embedding helpers. The [document model](/architecture/document-model/) follows
that path in source.
