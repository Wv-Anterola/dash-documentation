This ledger separates three claims that older project lists blurred together:

1. **Current product:** code and registries in the pinned `origin/master`.
2. **Branch implementation:** code that survives on another ref but is not
   contained in the canonical revision.
3. **Historical implementation:** code in reachable Git history that no longer
   survives at a branch tip.

A branch is an alternate line of code history. Something can work on that line
and still be absent from the application a reader runs today.

## What “complete reachable history” means

The generator:

- enumerates every local and origin ref and every reachable commit and object;
- classifies every reachable blob as source, test, build/config, generated,
  vendored, data, media, research artifact, or other artifact;
- parses each unique TypeScript/JavaScript or Python blob once by Git SHA;
- records unsupported formats and parser failures instead of dropping them;
- compares each ref with its merge base against `origin/master`;
- reports added, signature/documentation-changed, removed, and unreachable
  symbols;
- keeps declarations from removed implementations in a separate searchable
  historical index.

The comparison is semantic at the declaration level. It does not claim that a
syntax-resolved call proves runtime reachability; runtime tests and captures
remain stronger evidence.

## Rebuild it

```sh
npm run audit:branches
npm run audit:source
npm run audit:typedoc
```

The generators read Git objects and an immutable temporary archive. They never
check out or modify Dash-Web. `npm run coverage` rejects incomplete
classification, parser failures, mutable source links, missing refs, or
baseline mismatches.
