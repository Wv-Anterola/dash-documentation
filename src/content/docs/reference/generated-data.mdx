## What is published

Every dataset is derived from one pinned Dash-Web revision by a generator in
`scripts/`, committed alongside the pages that use it, and served as static
JSON.

<DatasetIndex />

A manifest of all of them, with schema versions and record counts, is at
[`/assets/data/index.json`](/assets/data/index.json).

## The shape of a dataset

Every dataset shares the same envelope:

```json
{
  "schemaVersion": 1,
  "generatedAt": "…",
  "repository": { "remote": "https://github.com/brown-dash/Dash-Web", "baseline": "<commit sha>" },
  "methodology": { "…": "how this dataset was derived, and what makes generation fail" },
  "summary": { "…": "counts the pages quote" },
  "<records>": [ … ]
}
```

The array name differs per dataset and is listed in the table above. Two fields
are worth reading before anything else:

- **`repository.baseline`** is an immutable commit. Every `source.url` in the
  dataset is a permalink into that commit, so a record can be checked against
  the exact code it describes. Note that `brown-dash/Dash-Web` is not publicly
  visible: those permalinks open for people with access to it and return a 404
  for everyone else. The file, line, and commit in the record are still exact,
  and these datasets are public, so the claim stays precise even where the code
  behind it is not reachable. This is set out under [who can open a source
  link](/reference/implementation-snapshot/#who-can-open-a-source-link).
- **`methodology.driftRule`** states what makes generation fail. That is the
  mechanism keeping the dataset honest: when the code it parses moves, the
  build breaks rather than the documentation quietly going stale.

## Stability

Fields are added, not renamed or removed, without incrementing that dataset's
`schemaVersion`. Treat a `schemaVersion` change as breaking.

The baseline moves whenever the pinned Dash-Web revision moves, and record
counts move with it. If you need reproducible results, pin the baseline you
read and compare against it rather than against "latest".

Two datasets need extra care:

- **`project-controls`** is the one dataset generated from something other than
  the pinned baseline. Each project record carries its own `branchTip` and a
  `mergedIntoMaster` flag, because these features live on unmerged branches.
  Read `disclosure` before using it for anything.
- **`task-routes`** contains hand-reviewed judgements about which controls
  serve one intent. The routes are machine-verified to exist; the grouping is
  editorial.

## For language models and other automated readers

The rendered HTML is the worst form of this site for a machine. The large
references build their record lists in the browser from the endpoints above, so
a crawler that reads the page sees a loading message where the records are.
Three plain-text entry points exist so that nothing has to guess:

| Endpoint | What it is |
| :--- | :--- |
| [`/llms.txt`](/llms.txt) | The [llmstxt.org](https://llmstxt.org) index: one line per page, grouped by section, with the caveats an automated reader needs before quoting anything. |
| [`/llms-full.txt`](/llms-full.txt) | The full prose corpus of every page in one fetch. Generated tables are not inlined; each is replaced by a pointer to its JSON. |
| [`/robots.txt`](/robots.txt) | Crawling is allowed, and the sitemap and the two files above are named in it. |

Both text files are built from the content collection and the dataset manifest
at build time, so a page that is added, retitled, or removed is reflected
without anyone remembering to update them.

If you are quoting this site, quote the commit rather than the page. Every
record carries `repository.baseline`, and every `source.url` is a permalink into
that commit; the pages themselves move whenever the baseline does.

## What is not published

The full source ledger, the semantic branch deltas, and the TypeDoc export run
to tens of megabytes each and are not served as endpoints. They are used at
build time to render the [module API pages](/technical/exported-symbols/), and
can be regenerated locally with the commands in [Reproducibility and artifact
packages](/research/reproducibility/).

## Using it

Nothing here requires a key, and everything is a plain static file. There is one
worked query per dataset below, each answering a question somebody actually
arrives with.

These are checked. `npm run examples` parses every field path in every example
on this page and resolves it against the real dataset, so a renamed field breaks
the build instead of leaving a copy-paste command that silently returns nothing.
That is the failure mode of documented examples everywhere, and it is invisible
without a check, because an empty result looks exactly like a correct answer of
"none".

### The interface

```sh
# Which controls are hidden outside Developer mode?
curl -s https://brown-dash-documentation.vercel.app/assets/data/interface-controls.json \
  | jq -r '.controls[] | select(.visibility | test("Developer mode")) | .label'

# Which right-click entries change the document without an undo batch?
curl -s https://brown-dash-documentation.vercel.app/assets/data/context-menus.json \
  | jq -r '.items[] | select(.undoable == false and .kind == "action") | "\(.surfaceName): \(.label)"'

# Which chords does Dash take away from the browser?
curl -s https://brown-dash-documentation.vercel.app/assets/data/keyboard-shortcuts.json \
  | jq -r '.shortcuts[] | select(.eventControl.preventDefault) | .chordOther'

# Which everyday tasks can be done by keyboard as well as by clicking?
curl -s https://brown-dash-documentation.vercel.app/assets/data/task-routes.json \
  | jq -r '.tasks[] | select(.routeKinds | index("shortcut")) | .intent'

# Which "open here" requests does nothing actually route, so they fall through?
curl -s https://brown-dash-documentation.vercel.app/assets/data/open-destinations.json \
  | jq -r '.destinations[] | select(.routed == false) | "\(.member) used \(.useCount) times"'
```

### The runtime and the server

```sh
# Which routes touch the database without going through the route manager?
curl -s https://brown-dash-documentation.vercel.app/assets/data/http-routes.json \
  | jq -r '.routes[] | select(.effects.database and .access == "direct-no-route-manager") | "\(.method) \(.path)"'

# Which document types is a person expected to create, rather than the system?
curl -s https://brown-dash-documentation.vercel.app/assets/data/document-types.json \
  | jq -r '.types[] | select(.audience == "surface") | "\(.name): \(.plainMeaning)"'

# Which stored field types can a script reach?
curl -s https://brown-dash-documentation.vercel.app/assets/data/field-types.json \
  | jq -r '.registrations[] | select(.scriptingGlobal) | "\(.tag) -> \(.className)"'

# Which scripting globals ship with no description at all?
curl -s https://brown-dash-documentation.vercel.app/assets/data/scripting-globals.json \
  | jq -r '.globals[] | select(.description == "") | .name'

# ... and which of those can still be understood from the button that calls them?
curl -s https://brown-dash-documentation.vercel.app/assets/data/scripting-usage.json \
  | jq -r '.usage[] | select(.described == false) | "\(.name) <- \(.controls[0].label)"'

# Which controls come from an unmerged project branch rather than from master?
curl -s https://brown-dash-documentation.vercel.app/assets/data/project-controls.json \
  | jq -r '.controls[] | select(.leavesDash) | "\(.projectName): \(.label)"'

# Where is a given exported symbol declared?
curl -s https://brown-dash-documentation.vercel.app/assets/data/exported-symbols.json \
  | jq -r '.rows[] | select(.name == "CompileScript") | "\(.module):\(.lineStart) \(.signature)"'
```

### The documentation itself

```sh
# Which surfaces have records nobody has explained anywhere?
curl -s https://brown-dash-documentation.vercel.app/assets/data/coverage-report.json \
  | jq -r '.surfaces[] | select(.unreachable > 0) | "\(.name): \(.unreachable) of \(.records)"'

# What is the tightest contrast ratio on this site, in light mode?
curl -s https://brown-dash-documentation.vercel.app/assets/data/accessibility.json \
  | jq -r '[.measurements[] | "\(.themes.light.ratio) \(.name)"] | sort | first'

# Which help links inside Dash point at a fragment that no longer exists?
curl -s https://brown-dash-documentation.vercel.app/assets/data/inapp-doc-links.json \
  | jq -r '.links[] | select(.fragmentStatus == "missing") | "\(.surface): \(.requested)"'
```

If you build something on these, the useful thing to report back is a record
that turned out to be wrong. The generators are designed to fail loudly on
structural drift, but a wrong plain-language explanation is exactly the kind of
error automation cannot catch.
