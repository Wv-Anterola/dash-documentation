## Why this page exists

The other references start from a thing and tell you what it does. That is the
wrong direction for someone who knows what they want and cannot find it. Worse,
when two routes look interchangeable but are not, no per-thing reference will
tell you, because neither entry knows about the other.

The most common way people get this wrong in Dash:

- **Closing is not deleting.** The tab close, the menu entry, and
  <kbd>Delete</kbd> all remove a document from view; none of them destroys it.
- **Grouping is not collecting.** <kbd>Shift</kbd> + <kbd>G</kbd> tags the
  selection with a shared group. The marquee's <kbd>G</kbd> and <kbd>C</kbd>
  build a new collection instead.
- **Copy does not copy content.** It writes document identifiers, so pasting
  outside Dash gives you a marker string.

Each of those is called out below, on the task it belongs to.

## How this page stays honest

The task list is written by hand: deciding that two controls serve one intent
is a judgement, not something a parser can decide. What is checked
automatically is whether each named route still exists. Every entry above is
resolved against the generated control, menu, and shortcut inventories when the
site is built, and generation fails if any route disappears or if a task drops
below two surviving routes.

That matters because a cross-reference is the first thing to rot in a
documentation set, and a rotted one is worse than none: it sends people looking
for a button that was renamed two releases ago.
