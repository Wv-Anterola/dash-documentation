## Verification method

Claims were checked against the type enum, `CollectionView.renderSubView`,
`CollectionView.setupViewTypes`, the `Agent` constructor, the
`DocumentContentsView.Init` component registry, and source paths recorded in the
capability registry.

The two commits after the previous snapshot changed context-menu positioning,
scrolling, and submenu rendering. They did not change the document, collection,
or agent registries, so the verified counts remain the same.

Project integration status remains evidence-backed prose maintained in
`src/data/projects.ts`, but it is no longer based on the current branch alone.
The [complete branch audit](/reference/branch-audit/) reads every unique source
version reachable from every local and origin branch tip and records the exact delta
of each branch from this master snapshot.

That separation matters:

- **current behavior** comes from this exact `origin/master` commit;
- **branch-only behavior** must be labelled implemented, prototype, or
  archived rather than integrated;
- **historical descriptions without source** remain documentation-only or
  unclear;
- **project workflows** name both the human interaction and the internal
  view/model/tool/service path recovered from code.

## Updating the snapshot

1. Fetch the intended Dash-Web remote.
2. Record the exact commit hash.
3. Run `npm run audit:branches` to read all branch-tip code versions.
4. Re-run registry inventory checks.
5. Inspect added and removed user entry points.
6. Update capability availability and source paths.
7. Update project statuses only with direct evidence.
8. Run documentation coverage, type, build, and link checks.
9. Record the change in release history.
