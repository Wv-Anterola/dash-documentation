The generated API answers “what declarations exist?” This reference answers
“what must remain true when they are used together?” It is the contract layer
between the [engineering model](/architecture/engineering-model/) and the
[source-generated modules](/technical/api/).

![A user action crosses input, undo, document, synchronization, storage, and rendering contracts before it is fully integrated.](/assets/images/diagrams/dash-runtime-contracts.svg)

## Contract vocabulary

| Term | Meaning in this reference |
| :--- | :--- |
| **Owner** | The object or service authoritative for a piece of state |
| **Precondition** | What the caller must establish before invoking the symbol |
| **Postcondition** | What a successful call makes true |
| **Side effect** | State changed outside the returned value |
| **Invariant** | A property that must hold before and after every supported call |
| **Failure semantic** | What remains changed, unresolved, retried, or reported when work fails |
| **Extension obligation** | What new code must test when it crosses the contract |

“Internal” below does not mean unimportant. It means the symbol is not a stable
third-party API; Dash itself depends on the behavior and can change the syntax
only by updating its callers and stored-state assumptions together.

## Document construction contract

### `new Doc(id?, forceSave?)`

**Responsibility.** Create the field container and return its proxy. The proxy
intercepts get, set, delete, enumeration, and access checks. When no ID is
provided, or `forceSave` is true, construction asks `DocServer` to create the
record.

**Invariant.** Code that expects document semantics must operate on the returned
proxy, not the constructor target. Field identity, observability, serialization,
and update emission depend on those traps.

**Failure semantic.** Before `DocServer.init`, persistence functions are bound
to an error function. Construction that tries to persist before initialization
fails instead of silently creating a disconnected durable document.

**Extension obligation.** Do not bypass a canonical factory for a specialized
document. Verify create, serialize, hydrate, mutate, undo, and reload.

### `Documents.Prototypes.get(type)` and `InstanceFromProto`

**Responsibility.** Select registered defaults for one document type and create
an instance/delegate that participates in normal document identity.

**Preconditions.** The type has a prototype registration and the factory knows
which values belong on data versus layout state.

**Postcondition.** The returned document has enough type and layout information
for the render dispatch to select a component before optional provider work
finishes.

**Failure semantic.** A type with no complete registry path may exist in source
but fail at creation, rendering, or reload. Registry presence is necessary but
not sufficient evidence of integration.

The [complete type lifecycle catalogue](/reference/document-types/) expands
this contract into every current prototype, primary field, factory, creator
template, collection variant, and layout component.

## Field ownership contract

### `Doc.GetProto(doc)`

**Responsibility.** Recursively follow `proto` until reaching a document marked
as a data document or a root with no distinct prototype.

**Invariant.** The prototype chain must terminate. Callers use the result as
shared data identity, so introducing a cycle or a non-document prototype breaks
more than inheritance.

**Side effects.** None expected; this is identity resolution.

**Extension obligation.** Test direct documents, delegates, nested delegates,
and old stored documents whose optional markers are absent.

### `Doc.SetInPlace(doc, key, value, defaultProto)`

**Responsibility.** Choose the durable owner of a field write:

- write on the delegate when it already owns the field;
- write on the data document when the data owner already owns the field;
- otherwise use `defaultProto` to choose data owner versus delegate.

Leading underscores are removed before the ownership check.

**Postcondition.** Exactly one resolved owner receives the new value through
the normal document setter.

**Failure semantic.** Choosing the wrong `defaultProto` may look correct in the
current view but change every embedding or disappear when a new context is
opened. The function cannot infer product intent from the field name.

### `Doc.GetLayoutDataDocPair(containerDoc, containerDataDoc, childDoc, layoutFieldKey?)`

**Responsibility.** Resolve the child layout to render and the optional data
context used by templates.

**Preconditions.** The child and its prototype are available. The container
context reflects the place where the child is being rendered.

**Postcondition.** Render code receives a layout document, plus data when the
template/context relationship requires it.

**Failure semantic.** A missing or still-pending child produces a warning and a
pair containing the unresolved child. A renderer must handle a loading or
missing value rather than dereference it as complete state.

## Field serialization and lazy-reference contracts

### `SerializationHelper.Serialize(obj)`

**Responsibility.** Preserve primitives directly and convert registered object
fields to `serializr` data plus a stable `__type` discriminator.

**Precondition.** Every object constructor has been registered through
`@Deserializable` and every durable member has a schema.

**Invariant.** The wire tag identifies the constructor needed to rebuild the
runtime behavior. A class name alone is not written as the protocol contract.

**Failure semantic.** Both `undefined` and `null` become serialized `null`. An
unregistered object constructor throws synchronously.

**Extension obligation.** Round-trip the new value as a top-level document field
and as a nested list value. Verify the runtime class, value, parent callback, and
cold-reload mutation behavior.

### `SerializationHelper.Deserialize(obj)`

**Responsibility.** Reconstruct a registered runtime value, then run its optional
post-deserialization repair.

**Postcondition.** The returned promise resolves only after `serializr` has
constructed and populated the instance and the registered repair callback has
been invoked.

**Failure semantic.** Runtime `null`/`undefined` input resolves to `undefined`.
An object without `__type` warns and resolves to `undefined`; an unknown type tag
throws.

**Extension obligation.** Preserve the serialized record and type tag in any
error evidence. Replacing an unknown value with a default would conceal a schema
or migration failure.

### `Deserializable(tag, repair?, constructorArgs?)` and `autoObject()`

**Responsibility.** Bind one stable wire tag to a constructor, optionally define
how constructor arguments are recovered, and provide the nested-object schema
used by documents and lists.

**Invariant.** Each tag is globally unique. Renaming the tag is a stored-data and
wire compatibility change even when the TypeScript class name stays the same.

**Failure semantic.** Duplicate registration throws during module loading.
Nested object errors propagate through the containing serialization operation.

### `ProxyField.value` and `setValue(field)`

**Responsibility.** Represent a relationship as a document ID, lazily hydrate
that identity, and share the client cache with every other reference to the same
document.

**Postcondition.** A successful resolution clears the waiting promise and exposes
the cached document. An undefined result clears the promise and marks the proxy
failed.

**Invariant.** The reference does not embed or clone the target document.

**Failure semantic.** A failed proxy instance does not automatically issue
another read. Recovery requires a new proxy, a direct forced read, or explicit
retry behavior at a higher layer.

### `new ListImpl(fields?)` and `ListImpl.__realFields`

**Responsibility.** Return an array-like proxy, attach parent/change callbacks to
object members, store document members as `ProxyField` identities, and hydrate
all unresolved members in one batch before real-value iteration.

**Invariant.** All newly discovered unresolved proxies share the same batch read
and one MobX action for result installation.

**Failure semantic.** `copyWithin` and `Object.defineProperty` are unsupported;
`fill` rejects `RefField` values. Individual list entries can resolve to
undefined when their document record is missing.

**Extension obligation.** Test append, removal, replacement, reorder, nested
mutation, duplicate values, missing references, concurrent edits, copy, undo,
serialization, and cold reload.

The complete value catalogue and mutation sequence are in
[field runtime and serialization](/architecture/field-runtime/).

## Rendering contracts

### `DocumentContentsView.Init(...)`

**Responsibility.** Install layout primitives, document renderers, and auxiliary
interface components before `MainView` renders.

**Precondition.** Client bootstrap has loaded the current user and user
document. Renderer dependencies are imported and their own initialization has
completed.

**Invariant.** A persisted user-facing type maps to a renderer that tolerates
missing optional fields and respects access checks. Registration must not create
a second durable store.

**Failure semantic.** Missing initialization or mapping can leave a valid
document represented by a fallback/loading surface. A successful factory test
does not prove this contract.

### `CollectionView.renderSubView(type, props)`

**Responsibility.** Dispatch a persisted `CollectionViewType` to a concrete
collection component while supplying the common child add, move, remove,
selection, sizing, and layout callbacks.

**Postcondition.** The selected view operates on the same collection members;
changing perspective does not convert or copy them.

**Failure semantic.** `undefined` returns no view. Safe mode rewrites selected
types to simpler renderers. An enum value without a dispatch is not a current
view capability.

**Extension obligation.** Verify empty, single, mixed, and large collections;
add/move/remove; perspective switch; save/reload; and a second embedding.

## Client synchronization contracts

### `DocServer.init(protocol, hostname, port, identifier)`

**Responsibility.** Reset the document cache, create a WebSocket-only Socket.IO
connection, bind document get/create/update functions, answer the server
handshake with the user identifier, and register incoming update/delete/server-
termination handlers.

**Precondition.** Call once with the current identity before persistent document
creation or reads.

**Failure semantic.** `connect_error` is logged to the browser console. The
client does not convert that event into a write retry queue. A server-termination
message displays the supplied recovery notice and reloads the page.

### `DocServer.GetRefField(id, force?)`

**Responsibility.** Preserve one client object identity for a document ID.
Return a cached document when available; otherwise request serialized state,
deserialize it, populate the cache, and resolve waiting references.

**Postcondition.** Concurrent readers of the same ID converge on the cached
document rather than independent copies. `force` refreshes an existing cached
document in place while suppressing server echo.

**Failure semantic.** A missing server record resolves as `undefined` and is
removed from cache. Callers must distinguish “not loaded yet” from “does not
exist.”

### `DocServer.GetRefFields(ids)`

**Responsibility.** Batch cold document reads, deduplicate cache work, hydrate
records, and periodically yield so the loading interface can update.

**Invariant.** Existing cached instances retain identity; a batch must not
replace an object already observed by views with an unrelated object.

**Failure semantic.** Missing records remain missing in the result map. The
loading counter is progress evidence, not proof that every requested ID exists.

### `DocServer.UpdateField(id, diff)`

**Responsibility.** Forward a serialized field operation when the client is
editable and the current user is not `guest`.

**Critical semantics.** Guest creation, updates, and deletes are not emitted.
Read-only mode replaces the update function with a no-op. The local document is
already observable, so the screen can change even when no durable operation was
sent.

**Failure semantic.** Standard updates have no client acknowledgement. A
WebSocket disconnection does not by itself roll local MobX state back.

**Extension obligation.** Persistence tests must reload from a cold cache under
an authenticated editable user. Seeing the field change in the initiating
window is insufficient evidence.

## Server ordering and persistence contracts

### `Message.Message`

**Responsibility.** Derive the actual Socket.IO event identifier as UUIDv5 of
the readable message name under the URL namespace.

**Invariant.** Client and server using the same readable name derive the same
wire event without sharing a separately generated constant.

**Failure semantic.** Changing punctuation, capitalization, or wording changes
the UUID and silently separates mixed-version peers unless compatibility is
provided.

**Extension obligation.** Treat message names as protocol identifiers. Test the
derived UUID, direction, payload, callback, origin behavior, and peer behavior.

### `WebSocket.initialize(isRelease, credentials)`

**Responsibility.** Start the Socket.IO listener, install connection and message
handlers, emit the handshake/statistics, and expose the server termination
helper.

**Postcondition.** Connections on the resolved socket port can invoke the
registered read, write, delete, gesture, utility, and statistics paths.

**Security precondition.** A production implementation must attach a trusted
server identity to each socket and authorize every operation before database
access. The current initializer does not establish those controls itself.

**Failure semantic.** The termination helper emits literal
`connection_terminated` with a timestamp; the client alert handler listens on
the deterministic UUID for `Connection Terminated` and expects a reason string.
The two paths do not currently interoperate.

The full event and acknowledgement catalogue is in the
[synchronization protocol reference](/reference/synchronization-protocol/).

### `WebSocket.UpdateField(socket, diff)`

**Responsibility.** Accept an operation only after the socket/user handshake,
append it to the queue for its document ID, and start dispatch when that ID has
no active operation.

**Invariant.** Operations for one document ID execute in arrival order.
Different IDs may progress independently.

**List behavior.** Add/remove operations read the current list, reconcile with
the client's length/hint, write a composite list, and may send the reconciled
state back to the initiating socket when concurrent structure differs.

**Failure semantic.** A socket without a mapped user is rejected by returning
`false`. The normal field path broadcasts after the database callback; it does
not return a durable receipt to the initiating client.

### `Database.update(id, value, callback, upsert, collectionName)`

**Responsibility.** Serialize writes for one ID through `currentWrites` and
apply MongoDB `updateOne` with the requested upsert policy.

**Precondition.** The database connection exists. Calls made before connection
are queued in `onConnect`.

**Postcondition.** On success, the per-ID write marker is removed when it still
points at the completed promise, the callback runs, and queued work can proceed.

**Failure semantic.** The current rejection path logs `MOngo UPDATE ONE ERROR`
but does not resolve the wrapper promise or invoke the callback. Later writes
chained to that unresolved per-ID promise may wait indefinitely. Recovery
requires confirming database health and restarting the affected runtime; a
browser-only retry is not proof that the queue recovered.

## Undo contract

### `UndoManager.StartBatch(name)` and `Batch.end()`

**Responsibility.** Increment nesting depth, open the shared event list when
needed, and commit that list only when the outer batch ends.

**Invariant.** Every successful `StartBatch` must end or cancel, preferably in
`finally`. Nested batches share the current event list; the outermost end
decides whether it enters history.

**Failure semantic.** Ending the same `Batch` twice logs a warning. A batch that
never ends leaves nesting depth nonzero and can absorb later events. Canceling
the outer batch prevents the collected events from entering history; temporary
batches can actively replay their inverse events on failure.

### `UndoManager.AddEvent`, `Undo`, and `Redo`

**Responsibility.** Record inverse/forward functions only while a batch is open
and not currently replaying. Undo applies inverse events in reverse order; redo
applies forward events in original order.

**Invariant.** Event functions must not recursively add new history while being
replayed. The `undoing` flag enforces that at the manager boundary.

**Extension obligation.** Assert the number and name of undo steps, the state
after undo, and the state after redo. An action that merely “has undo code” has
not met the contract.

## Link navigation contract

### `LinkFollower.FollowLink`

**Responsibility.** Resolve the opposite endpoint, prefer an already visible
target, otherwise open or navigate to a context containing it, then apply the
link's view/highlight behavior.

**Preconditions.** The link and endpoint references resolve, and the user can
read the destination.

**Invariant.** Following a relationship does not copy the target. Navigation
preserves document identity and treats contextual layout separately.

**Failure semantic.** Missing, private, or contextless targets require a
non-destructive no-target outcome. Link UI must not reveal inaccessible endpoint
content through titles, previews, backlinks, or agent results.

## Agent execution contract

### `Agent.execute(...)`

**Responsibility.** Continue the model/tool loop, validate a selected tool and
its parameters, call the registered implementation, append observations to
conversation state, and stream processing/answer updates.

**Preconditions.** The tool is registered, its schema accepts the arguments,
and the requested scope is authorized. External and workspace effects are
identified before execution.

**Invariant.** Model text is not authority. Only a registered tool can cross
from generated output into application behavior.

**Failure semantic.** Tool, provider, parse, and validation failures remain
distinct. A write tool must report what changed before failure and keep related
workspace mutations in one undo batch. External effects need compensation when
they cannot be undone.

**Branch distinction.** The canonical execution path invokes the validated tool
directly. The oversight research branch inserts provenance capture around that
call; that wrapper is not part of the canonical contract.

## End-to-end contract proof

A feature that changes durable state should pass this sequence:

1. Create it through the documented entry point.
2. Perform one named action as an authenticated editable user.
3. Verify the intended data owner and contextual layout owner.
4. Undo once and verify the complete prior state.
5. Redo once and verify the complete new state.
6. Reload from a cold cache and verify persistence.
7. Open the same document in a second context and verify shared versus local
   fields.
8. Repeat with a second client where concurrency matters.
9. Interrupt the relevant server, database, worker, or provider boundary and
   verify a truthful failure state.
10. Restore the boundary and verify recovery without creating duplicate or
    partial records.

Use [Troubleshooting Dash](/development/troubleshooting/) to isolate a failed
step. Use the [generated API](/technical/api/) to inspect exact signatures and
immutable source locations.
