## Three words the interface assumes you know

| Word | Deliberately simple meaning |
| :--- | :--- |
| **Button** | Something you click to perform an action or open a panel. A button is a control; it is not saved content unless it is specifically the **Button** creator. |
| **Document** | One saved thing in Dash: a note, picture, collection, map, task, agent, link, or other content object. |
| **Node** | Usually a document as you can see it inside a canvas, collection, graph, or agent view. “Create a node” normally means “create a document and show it here.” |

If an instruction says **select the node**, click the visible document. If it
says **open its properties**, keep that document selected and open the right
panel. If it says **create a node**, use a creator in **Tools** or type `:` on a
canvas.

The inventory combines three kinds of evidence:

- runtime captures, used to show where a person sees each control;
- the control registries and JSX in `TopBar.tsx`, `CurrentUserUtils.ts`,
  `DocumentButtonBar.tsx`, and `PropertiesView.tsx`;
- the document, creator, and scripting-global indexes generated from the Dash
  source tree.

The captured runtime and checked-out TypeScript are not perfectly identical.
The captured compiled client exposes **Trip Planner Tool** and **Trip Doc**
creators that are not recoverable as dedicated entries in the checked-out
`creatorBtnDescriptors` registry. The source registry, meanwhile, contains
newer developer and agent creators that the captured runtime does not expose.
The creator cards identify the runtime and source-registry states separately so
the difference remains explicit.

## The persistent frame

![The current Dash workspace with the top bar, context toolbar, sidebar, tab strip, freeform canvas, map, planner, and panel handles visible.](/assets/images/current/dash-trip-planner-workspace.webp)

The interface is layered:

1. The **top bar** changes the application or dashboard as a whole.
2. The **context toolbar** changes with the current selection.
3. The **sidebar** opens persistent collections and creation surfaces.
4. **Document decorations** appear around selected documents.
5. The **properties panel** exposes the selected document’s fields and view
   configuration.
6. **Tabs and tiles** determine which documents occupy the workspace frame.

When a control is missing, first clear the current selection, leave Explore
mode, and check whether Dash is in Novice or Developer mode. Many controls are
conditional rather than broken.

### How a toolbar click becomes a Dash state change

Most context-toolbar controls are documents themselves. Their source descriptor
declares a visible `title`, tooltip, button type, optional `toolType`, scripts,
and functions such as `hidden` or `linearView_isOpen`. Startup code turns that
descriptor into a `FontIconDocument`. The icon renderer evaluates the visibility
function and invokes the registered script when the person clicks, chooses a
value, or drags a slider. The script name resolves through `ScriptingGlobals` to
an implementation function, which then reads or writes the selected document,
its layout delegate, or a manager singleton.

The short script parameters mean:

| Parameter | Plain meaning | Technical role |
| :--- | :--- | :--- |
| `value` | The color, number, text, or list choice the person just supplied. | Passed by the document-backed button renderer into a value script. |
| `this.toolType` | Which sub-tool this button represents. | A descriptor field used by shared handlers such as `showFreeform`, `setFontAttr`, and `setActiveTool`. |
| `_readOnly_` | “Check the current value” instead of “change it,” when true. | Lets one script support both button-state evaluation and mutation. |
| `_added_` | Whether a dynamic toggle was added or activated. | Used by tag-filter controls to update a collection’s filter set. |
| `shiftKey` / `altKey` | Whether Shift or Alt was held during the action. | Selects alternate behavior, such as creating a perspective or pinning extra view state. |

The generated contracts intentionally keep the visible behavior and technical
trace together. A handler name alone is not an explanation, and a friendly
tooltip alone is not implementation evidence.

## Top bar

| Control | What it does | What to expect |
| :--- | :--- | :--- |
| **Home** | Leaves the active dashboard and returns to the dashboard home screen. | The dashboard remains saved; this is navigation, not deletion. |
| **Explore** | Toggles browsing mode for directly navigating to documents. | Clicking a document centers or opens it instead of selecting it for editing. Active Explore mode changes the button styling and hides incompatible editing controls. |
| **Dashboard title** | Opens the active dashboard’s context menu. | The menu contains dashboard-level operations; it is not only a label. |
| **Share** | Opens sharing for a dashboard you administer. | On a shared copy without admin access, the label becomes **View Original**. |
| **Issue reporter** | Opens the bug and feature-reporting surface. | Existing issues can be inspected before a new report is filed. |
| **Help** | Opens **Documentation**, **Tutorial**, and **Ask AI!**. | Tutorial re-enables contextual explainers. Ask AI creates a Dash help-assistant chat in a new pane. |
| **Settings** | Opens account, mode, appearance, and application settings. | Novice/Developer mode changes can make additional controls appear immediately. |
| **Heart / broken heart** | Shows server reachability and version state; opens server statistics. | Blue means connected and current, yellow means connected to a different version, and a broken red heart means the connection is down. |

## Sidebar panels

The panel buttons are document-backed menu controls. Clicking a selected button
closes its flyout; clicking another switches the flyout without changing the
workspace documents.

| Panel | Purpose | Important behavior |
| :--- | :--- | :--- |
| **Dashboards** | Lists dashboards in the older developer-mode sidebar. | Hidden in Novice mode because the current home screen is the primary dashboard manager. |
| **Search** | Searches titles, content, and metadata in the active scope. | <kbd>Ctrl/Cmd</kbd> + <kbd>F</kbd> toggles it. The type dropdown narrows results. |
| **Files** | Organizes documents into folders independently of their canvas location. | Includes **My Dashboards** and **My Recently Closed**; double-click or drag a listed document to reopen it. |
| **Tools** | Creates documents, templates, special workspaces, and overlays. | Click creates in the default destination; drag controls placement. The complete palette is below. |
| **Imports** | Receives imported files, URLs, and structured data. | <kbd>Ctrl/Cmd</kbd> + <kbd>I</kbd> toggles it. Importing creates Dash documents; it does not merely upload opaque files. |
| **Shared** | Lists documents and dashboards shared with the current user. | A badge indicates unseen shared items. Access still depends on document ACLs. |
| **Trails** | Lists presentation trails for the active dashboard. | <kbd>Ctrl/Cmd</kbd> + <kbd>R</kbd> toggles it. **New trail** creates a presentation path. |
| **Image Grouper** | Runs the image-grouping workflow. | This is a specialized collection surface, not a normal folder. |
| **Faces** | Opens the recovered unique-face collection. | It is a specialized computer-vision workflow and may depend on prior image processing. |
| **User Doc** | Exposes the current user’s system document. | Developer mode only. Treat it as implementation state, not an ordinary note. |
| **Recently Closed** | Stores closed documents until explicitly emptied. | Hidden as a standalone sidebar button; Files embeds it. Closing a document is not deletion. |

## Context toolbar

The strip below the top bar is selection-driven. Some controls are global
defaults; others mutate only the selected document or collection.

| **Pin** | Pin current view to a trail | Saves a presentation step from the current selection or view. Modifier keys determine whether content/view state is included. |
| **Header** | Header/title-bar color | Changes document chrome, not the content background. |
| **Template** | Default note template | Makes the selected note layout the default for newly created notes. |
| **Img Temp** | Default image template | Makes the selected image layout the default for new image documents. |
| **Fill** | Fill/background color | Changes the selected document or view background. |
| **Border** | Border color | Changes the selected document border. |

| **Chat** | Toggle chat assistant | Shows or hides the freeform assistant associated with the workspace. |
| **Ink** | Ink tool group | Expands drawing, width, color, eraser, mask, label, and Smart Draw controls. |

## Document decorations

Selecting a document can show a small action bar on or near its chrome. Its
contents vary with permissions, mode, and document capabilities.

| Decoration | What it does | Variants and cautions |
| :--- | :--- | :--- |
| **Links/count** | Opens the document’s links and begins a new link. | A link may target a whole document or an anchor returned by its view. |
| **Link search** | Searches for a target instead of dragging to one. | Useful when the destination is not visible on the current canvas. |
| **Linked trail** | Opens or creates the trail associated with the document. | This is a link relationship, not the global list of all trails. |
| **Follow primary link** | Makes clicking the document follow its primary link. | When enabled, selection behavior changes; the button remains highlighted. |
| **Finish link** | Completes an in-progress link on the selected target. | Flyout variants save layout state, content/view state, or both on the endpoint. |
| **Customize layout / embedding** | Opens the template menu; dragging creates an embedding. | Hidden in Novice mode because it edits the layout layer directly. |
| **Pin to trail** | Adds the document to the active presentation trail. | Shift saves layout, Alt saves content/view state, Shift+Alt saves both; the calendar variant schedules instead. |
| **Edit with AI** | Opens the document’s supported AI editor. | Only appears when the renderer declares an AI editor. A drag gesture can invoke Smart Draw in a parent view. |
| **Tags** | Shows or hides document tags. | Shift also applies the visibility choice to supported face annotations. |
| **Sharing** | Opens document-level sharing. | Only shown when the full link/action menu is enabled and permissions allow it. |
| **Context menu** | Opens the complete right-click menu for the selected content. | The entries depend on document type, mode, and access. Every entry it can contain is traced in the [right-click menu atlas](/reference/context-menus/). |

## Properties panel

![The current Dash Properties panel showing title, type, fields, options, links, generation, transforms, contexts, and filters.](/assets/images/current/dash-properties-panel.webp)

| Section | What it controls | Scope |
| :--- | :--- | :--- |
| **Title** | The selected document’s displayed title. | Data/prototype title depending on the selected view. |
| **Type** | The renderer or collection perspective currently in use. | Read this before changing type-specific fields. |
| **Fields & Tags** | Typed document data, metadata, and tags. | Advanced mode exposes more fields; direct field edits can affect scripts and views. |
| **Options** | Appearance and interaction settings. | Usually applies to the selected layout/view rather than every instance. |
| **Linked To** | Links and anchors connected to the selection. | Deleting a link removes the relationship, not its endpoint documents. |
| **Firefly / generation** | Supported image-generation or editing controls. | Requires the configured external service and only appears for compatible selections. |
| **Transform** | Width, height, position, and related layout values. | Values are layout coordinates, not intrinsic media dimensions. |
| **Other Contexts** | Other collections that contain the same document. | These are additional views of the same document, not copies. |
| **Filters** | Rules controlling which collection children render. | Filters affect visibility; they are not a delete operation. |
| **Sharing & Permissions** | Users, groups, and access levels. | Developer mode only. Nested content can have stricter permissions than its parent. |
| **Layout** | Raw layout fields and templates. | Developer mode only; use when building or diagnosing a renderer. |
| **Presentation variants** | Visibility, progressivize, media, media options, and transitions. | Replaces ordinary properties while editing selected trail slides. |

## Tabs, tiles, and canvas controls

The tab and tile chrome is the one part of Dash that Dash does not draw. The
frame comes from GoldenLayout, and Dash then **unbinds some of its click
handlers and substitutes its own**. Two controls consequently do something
other than their upstream name suggests, and knowing that explains behavior
that otherwise looks arbitrary.

| Control | What actually happens | Worth knowing |
| :--- | :--- | :--- |
| **Tab title** | Editing it writes `doc.$title`, in an undo batch named `edit tab title`. | The tab name is the document title. Renaming here renames it everywhere. |
| **Tab type icon** | Click opens the document's menu; drag places another view of the same document. | One pointer handler serves both gestures, so a small drag during a click changes what happens. |
| **Tab lightbox icon** | Opens the document full-screen over the workspace. | The tab stays where it is. An iconified document is de-iconified first. |
| **Tab x** | Routes through `tabDestroyed`, which adds the document to Recently Closed. | Not a delete. A document still embedded elsewhere is *not* added to Recently Closed, and presentation and key/value tabs are excluded. |
| **Tile +** | This is GoldenLayout's **popout** control with its handler replaced. It creates a freeform canvas named `Untitled Tab N`. | It does not pop the tile into a browser window. The counter lives on the dashboard as `$myPaneCount`. |
| **Tile x** | Dash replaces GoldenLayout's close handler with its own, batched as `close stack`. | Dash refuses to close the last tile and raises a raw browser alert reading `cant delete the last stack`. |
| **Tile maximize** | Dash *adds* to GoldenLayout's handler rather than replacing it, then persists the layout. | Upstream maximize still runs, so this one behaves as its name implies. |
| **Empty tile background** | Clicking the empty-tile message creates the same new canvas tab the plus control would. | The hit test looks for the element under the pointer rather than binding a handler. |
| **Dragging a tab** | Batched as `tab move`. An aborted drag cancels the batch and rebuilds the layout from the saved configuration. | A cancelled move leaves no undo entry at all, by design. |
| **Dragging a canvas document to the tab bar** | `StartOtherDrag` builds a GoldenLayout config and hands the gesture to a synthetic drag source. | This is why the drag changes character mid-gesture. Several documents at once dock as a row. |
| **Grey side handle** | Opens or closes the adjacent sidebar or properties panel. | Panel state only; no document is moved. |
| **Canvas –** | Zooms out. | Zoom is view state, not document state. |
| **Undo / Redo** | Reverses or reapplies named action batches. | Yellow indicates an action is still in flight. |
| **stack** | Opens the undo history so the workspace can jump to an earlier action. | Named batches are what you are jumping between. |
| **Toggle** | Switches the relevant mode or control state in the bottom canvas toolbar. | Its exact target depends on the active view. |

Each traced row above is in the searchable reference with its source line;
filter it to **Tabs and tiles** to read the handler expressions.

The full drag-and-drop procedures are in [The Dash
workspace](/getting-started/environment/). Keyboard equivalents are in

## Controls inside project-shaped workspaces

A project can add its own tabs and controls without creating new global
concepts. The current Trip Planner is the clearest example:

- **Plan / Prepare / Today / Recap** change workflow phase.
- **Map** opens the linked map document.
- **Planner** opens the planning tool.
- **Overview** exposes shared trip data.
- **Search / Plan** inside the planner change the planner subview.
- A day summary expands stops and can center them on the map.

Those controls are documented end to end in the [Trip Planner operating
guide](/guides/features/trip-planner/). Project-specific controls belong in
their project guide, while any reusable document, view, link, agent, or
properties behavior must also update its canonical capability documentation.

## If a label is still unexplained

Treat that as a documentation defect. Record:

1. the visible label or icon;
2. the selected document type and mode;
3. where it appeared;
4. the action taken and resulting state;
5. a synthetic screenshot with enough surrounding chrome to locate it.

Then update this atlas, the relevant operating guide, and—when the behavior is
reusable—the [capability catalog](/capabilities/). A tooltip alone is not
complete documentation.
