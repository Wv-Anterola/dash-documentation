## The common pattern

Good Dash workflows follow the same sequence:

1. **Capture** source material without losing provenance.
2. **Name** documents and fields so people and tools can find them.
3. **Organize** with collections and perspectives.
4. **Connect** claims, evidence, and context with precise links.
5. **Interpret** through notes, charts, comparisons, or agent assistance.
6. **Communicate** through a trail or shared workspace.
7. **Review** permissions, generated output, links, and undo state.

Dash is strongest when each stage preserves the previous one. A presentation
should still lead back to its source; an agent-generated category should still
be reviewable; a chart should still expose the records behind it.

## Before using a recipe

- Work in a collection with a clear title.
- Use synthetic or non-sensitive data while learning.
- Confirm external API credentials and data-sharing expectations.
- Keep important originals outside Dash as well as in the workspace.
- Treat project pages as provenance, not operating instructions.
