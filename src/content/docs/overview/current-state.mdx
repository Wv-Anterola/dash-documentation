This page is the honest inventory. Everything listed as present was checked
against the current `master` branch of Dash-Web rather than inferred from a
merged branch or a demo recording.

## Counts

Fifty-one document types, twenty-one collection views, and twenty-two agent
tools registered at startup. Those numbers come from three enums and one
constructor:

- `DocumentType` in `client/documents/DocumentTypes.ts`
- `CollectionViewType` in the same file
- the tool registry in `chatbot/agentsystem/Agent.ts`

## What works today

**Documents.** Rich text, images, web pages, PDFs, video, audio, recordings,
ink, and collections, all sharing one document implementation. Newer types
include 3D model viewing and sketching, data visualisation from CSVs, video
generation, policy analysis, life-coach workspaces, scrapbooks, journals,
tasks, and equations with a symbolic solver.

**Collections.** Freeform canvas, schema table, stacking, notetaking, tree,
carousel, grid, masonry, pivot, calendar, and a link graph. Switching between
them converts nothing.

**Linking.** Links anchor to regions, selections, PDF pages, ink strokes, and
timestamps. A link is itself a document, so it carries its own description.

**Trails.** Prepared paths through a corpus that you can leave at any point,
with spring-based transitions and support for branching.

**AI.** Two surfaces. A retrieval-augmented chatbot that answers with citations
resolving back to source documents, and an agent with twenty-two tools that can
filter, sort, tag, link, and create documents.

**Desktop.** Electron builds for macOS and Windows, and an agent service that
talks to a local Ollama instance, so the AI features can run against a model on
your own machine instead of a remote API. You install Ollama separately; the
build does not yet ship it.

## Where the implementation stops

These are limits worth knowing before you plan work around them.

Document types cannot be defined outside the core enum, so every new type edits
the same two files and two cohorts adding types in one term will conflict.

Collection views do not compose. A calendar of stacks is not expressible.

Links have no type or strength, so a citation and a passing association are
indistinguishable except by a description someone remembered to write.

The agent has no permission model. A tool that can write can write to anything
the user can, and the agent decides when to call it.

Generation quality is not evaluated anywhere in the codebase.

## Reading status labels

Every project on this site carries one of six labels, and the distinction that
matters is between *integrated* and everything else. Integrated means it can be
pointed at in the current `master` branch: a registered document type, an entry
in `CollectionViewType`, a tool in the agent registry, or code one of those
calls. A merged branch does not qualify, and neither does a demo recording or a
finished report.

The [status taxonomy](/reference/status-taxonomy/) defines all six labels and
the evidence each one requires.
