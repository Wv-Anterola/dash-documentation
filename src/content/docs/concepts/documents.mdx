## The idea

Everything in Dash is a document. A PDF is a document. A collection holding
forty PDFs is a document. The link between two of them is a document, and so is
a chat message, a presentation trail, and an agent.

They differ by their `type` and by which fields they carry, not by being
different kinds of object in the code.

## Why it matters

Most of what Dash can do is a consequence of this one decision.

Consider linking. If a link were a row in a table mapping one document id to
another, then giving it a label would mean adding a column, annotating it would
be impossible, and putting a link inside a collection would be meaningless.
Because a link is a document, all three come for free, and none of them needed
special-casing.

The same argument applies each time someone adds a type. When the 2026 cohort
added policy-checker documents, they did not have to teach the layout system,
the linking system, or the sharing system about policy checkers. Those systems
operate on documents.

## How Dash represents it

`client/documents/DocumentTypes.ts` declares the 51-value `DocumentType` enum.
Renderer modules register 50 prototype-backed types in the shared
`TemplateMap`; `client/documents/Documents.ts` supplies canonical factories and
prototype accessors. Most instance factories call `InstanceFromProto` with a
prototype fetched by `Prototypes.get(DocumentType.SOMETHING)`, but system,
sentinel, data-only, and prototype-resource paths intentionally differ. The
[complete type/prototype/factory catalogue](/reference/document-types/) records
every case.

### Identity and references

`Doc` extends `RefField` (`src/fields/RefField.ts`), which gives every document
a GUID at construction and makes it serialisable through
[serializr](https://github.com/mobxjs/serializr). That identifier is the only
thing a reference needs.

A field that points at another document does not hold the document. It holds a
`ProxyField` (`src/fields/Proxy.ts`), which stores the target's id plus a
MobX-observable cache and a promise for a load already in flight. Reading a
proxy either returns the cached document or returns `FieldWaiting` while
`DocServer` fetches it.

This is why a canvas with two thousand documents on it is not two thousand
loads: the collection holds proxies, and a document is fetched when something
actually reads it.

### Prototype delegation

`Doc.Get(doc, key)` walks the prototype chain. Passing `ignoreProto: true` reads
only the document's own fields, which is the distinction between "what is this
document's title" and "what title does it inherit".

`Doc.MakeDelegate` creates a document whose prototype is the original, so it
starts with everything the original has and diverges only where you write to it.
`Doc.MakeCopy` duplicates instead. `Doc.GetProto` walks up one level and
`Doc.GetDataDoc` recurses to the root, which is how a view knows which document
actually owns the content it is rendering.

### Layout and data are different documents

A document that appears in two places has one data document and a layout
document per appearance. Position, size, and scroll state live on the layout
side; the content lives on the data side. `Doc.GetLayoutDataDocPair` is what
resolves the two for a given render.

That split is what makes [other contexts](/guides/properties/othercontexts/)
work: the same content, two positions, no copy.

### The schema

`src/fields/documentSchemas.ts` declares `documentSchema` through
`createSchema`, giving typed accessors for the keys Dash itself relies on:
`title`, `type`, `author_date`, `x`, `y`, `zIndex`, `_nativeWidth`,
`_layout_scrollTop`, `_layout_currentTimecode`, and around a hundred more.

`links` is declared there as a computed read-only list, which is why a document
knows its own links without anything writing them onto it.

Documents are not limited to schema keys. Any key can be set, which is what
makes tagging, filtering, and the schema view work across types that were never
designed to have anything in common. The schema exists to type the keys the
system reads, not to constrain the ones you add.

Sharing is a field too. `updateCachedAcls` maintains symbol-keyed access-control
entries on the document, resolved through `HierarchyMapping`, which is why
permissions travel with a document rather than living in a separate table.

:::note[Integration contract]
A user-facing type needs a stable serialized value, prototype, factory or other
construction path, reachable creator/import workflow, layout component,
`DocumentContentsView` registry entry, persistence behavior, permissions,
undo, tests, and documentation. An enum member alone is not a feature.
:::

## Current limitations

Several types are intentionally domain-specific. `POLICY_TESTIMONY`,
`LIFECOACH`, `LCEVENT`, and `SCRAPBOOK` represent research workflows while
remaining compatible with shared document behavior. Types cannot currently be
declared by an external extension package, so additions touch the central enum,
prototype/renderer registration, and construction surfaces. Concurrent type
work therefore needs coordinated integration review.

The prototype system has no migration story. If a prototype's field layout
changes after documents already exist, those documents keep the old shape.
